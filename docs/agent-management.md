# Agent 管理

Agent 管理統一各 AI（目前為 Codex、Claude 與 Antigravity）的執行狀態、登入入口及桌面程式管理。執行任務透過 CLI；桌面 App 不必保持開啟。

## 頁面項目

| 區域 | 項目與用途 |
| --- | --- |
| 總覽 | 三個 Agent、支援內容、協作角色、CLI 狀態、登入觀測、最近執行紀錄、版本 |
| 頁首 | 本機服務狀態、CLI 就緒數量、上次檢查時間與重新檢查 |
| 執行與登入 | 能力檢查結果、登入觀測、最近執行、錯誤原因及提供者官方登入入口 |
| 桌面 App | 是否安裝／開啟、程序是否由 Clau-dex 管理、開啟與自有程序關閉 |
| 進階診斷 | 預設收合的 CLI 版本、完整命令路徑、複製路徑及桌面程序編號 |
| 本機服務詳細資料 | 預設收合的 loopback 端點、PID、MCP 工具及啟停控制 |

選取「詳細資料」會在右側顯示該 Agent；此時不重複顯示聊天室的用量／系統觀察面板。離開管理頁會恢復原先觀察面板偏好。可按 Escape 關閉 Agent 詳情，焦點回到對應的詳細資料按鈕。

## 狀態與操作

`src/agent-readiness.js` 的純函式由管理頁、聊天室參與者選項、系統面板及傳送 gate 共用。它以提供者資料與最新 CLI 檢查判斷，沒有讀取秘密值或以桌面 App 存活推斷可用性。

| 狀態 | 意義 | 操作 |
| --- | --- | --- |
| 狀態待確認／正在檢查 | 尚未取得可用資料 | 等待檢查或重新檢查 |
| CLI 不可用 | 找不到可執行或相容的 CLI | 查看修復方式，檢查詳細錯誤與命令路徑 |
| 需要登入 | CLI 明確回報未登入 | 前往登入，再由提供者完成授權 |
| 等待授權 | 登入流程進行中 | 完成提供者授權，暫停傳送 |
| CLI 已登入 | CLI 能力與官方登入狀態檢查通過 | 前往聊天室 |
| CLI 可用 | 本機能力檢查通過，登入有效性仍待實際請求確認 | 前往聊天室 |
| 服務未啟動 | CLI 就緒，但本機橋接已停止 | 在服務詳細資料啟動橋接 |

Antigravity 的憑證存在／不存在／無法確認是獨立觀測；不會據此宣稱已驗證登入，也不因缺少該標記單獨禁止嘗試任務。最近執行紀錄來自已保存的 Agent stage 與時間，與 CLI、帳號狀態分開顯示；成功紀錄不保證下一次請求成功。

「前往聊天室」建立由所選 Agent 單獨處理的新對話，不送出訊息，也不改寫原先全域 Agent 偏好。一般「新對話」仍使用上次保存的 Agent 組合。已有草稿會保留在原對話。

## 刷新、用量與程序管理

- 「重新檢查」及頂部狀態刷新只執行本機狀態檢查，不查詢模型；重新整理會保留診斷展開與可辨識操作的鍵盤焦點。
- 用量面板的「更新 Claude 額度（使用少量用量）」才明確要求額度更新，受既有快取與節流限制。原有啟動時快取過期更新行為仍保留。
- 開啟桌面 App 不會啟動任務。外部開啟的 App 顯示自行關閉的說明，只對 Clau-dex 自有的存活程序提供關閉按鈕。
- 關閉 Clau-dex 仍依原有生命週期停止管理服務與自有任務；不加入常駐、開機啟動或安全繞過設定。

## 驗證

`npm test` 包含共用狀態模組的優先順序、憑證三態、不變性及可傳送性測試。

手動執行 `npx electron test/electron-agent-management-smoke.mjs` 可驗證真實 renderer／IPC 的三 Agent 同屏、詳細資料、狀態切換、服務 gate、焦點保存、窄視窗及選定 Agent 建立新對話。此測試使用隔離資料與假提供者，不呼叫模型或桌面 App；結果寫入 `.bridge/agent-management-smoke/report.json`。

## 新增或移除 AI

畫面上所有和 AI 有關的項目都依 `src/providers.js` 的註冊表產生，包括：
- 參與的 AI 晶片、統籌方選項；
- 思考強度滑桿；
- 歡迎文字、輸入框提示、接手說明；
- 額度與 Token 用量列、圖例；
- Agent 管理卡片與系統面板；
- 頭像、晶片與訊息配色。

新增或移除註冊表中的項目後，上述畫面會自動跟著增減，不必修改 `ui/`。`test/provider-ui.test.js` 會檢查畫面程式沒有寫死個別 AI；如果有人再把某個 AI 寫進畫面，測試就會失敗。

在註冊表中新增 AI 時，要填寫的欄位：

| 欄位 | 用途 |
| --- | --- |
| `name`、`appName`、`cli` | 顯示名稱、桌面 App 名稱、CLI 執行檔 |
| `coordinate`、`tasks`、`images` | 能否統籌與複核、能否接聊天室任務、能否收圖片 |
| `login`、`status`、`credentialTarget`、`signInWith` | 登入與狀態檢查方式 |
| `effort` | CLI 接受的思考強度等級，第一個必須是 `auto`（不傳參數）；沒有就填 `null`，畫面不顯示滑桿 |
| `quota` | 方案額度的資料來源說明；無法查詢就填 `null`，畫面顯示「暫不支援查詢」 |
| `theme` | 圖表色與深淺三階；`ink`／`text`／`soft`／`line` 為頭像、晶片與訊息的配色，可省略 |

圖示使用 `ui/index.html` 中的 `<symbol id="i-<id>">`。沒有對應圖示時，會改用中性圖示。

以下後端部分仍需依提供者的 CLI 實作，畫面不會自動處理：
- `src/agent-runtime.js`：任務執行與結果判讀。
- `src/cli-discovery.js`：官方預設安裝位置。
- `src/app-manager.js`：桌面 App 的 AppID 與程序白名單。
- `src/usage-monitor.js`：本機用量與額度讀取。
